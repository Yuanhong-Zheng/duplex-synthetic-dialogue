[TASK STYLE CONTRACT]
`task_style` 是代码冻结的 episode-level 任务形态，模型不得修改。它描述本次对话主要依赖什么信息，不是某一轮的 Act、Timing 或 topic 数量。

- `开放式互动`：主要依赖通用知识、解释、建议、练习、创作或主题讨论，可以围绕一个或多个相关或不相关主题自然展开。
- `结构化整理`：主要依赖用户随后提供的材料、候选、记录或条件，并产出整理、分类、比较、筛选、核对、排序或计划等结果。
- `混合型`：通用知识/规则与用户随后提供的材料或个人条件都发挥作用，对话可以推进到比较、选择、判断或调整。goal 不要求按“先通用规则、再用户材料”的固定顺序表达，也可以从具体经历、待判断的问题、冲突或选择切入，再在对话中补充或交替使用通用框架。
- `常识问答`：围绕一个简单 topic 形成轻量多轮问答，goal 不要写得过于复杂或合并多个独立任务，但可以保留自然追问空间。

topic transfer 可以出现在三种 style 中，但临时换题本身不构成混合型。

`example_tasks` 是当前 `task_style` 下的示例任务方向，不是模板或配额。它们提供可借鉴的任务主题、对象和互动方向；可以选择其中一个方向，或在其基础上构造同一 Scenario 的新变体，但不要复制示例措辞或句式。在不偏离 Scenario 和冻结 style 的前提下自由发挥，不要为了多样性虚构不合理的风险、外部结果、工具能力或事实。

如果是批量模式，列表中的候选必须整体多样：自然改变用户关系、触发原因、任务阶段、关注重点、期望结果和表达入口，不能只是替换地点、人物、数字、候选名称或句首。不要机械地为每条分配一个维度，也不要牺牲 Scenario 合理性来追求形式差异。

[TASK DIVERSITY]
阅读 `previous_task_goals` 后，把它当作当前 Scenario、当前 task_style 已经覆盖过的现实使用方式。在不偏离当前 Scenario、冻结 task_style 和 audio-only 能力边界的前提下，优先寻找尚未出现、自然且具有代表性的 task goal；不要只替换地点、数字、候选名称、例子或形容词。

历史 goal 已集中在某一种现实情境、人物关系、使用阶段或互动入口时，换一个自然的切入方向。可按当前 Scenario 的实际可能性改变用户所处的地点或生活场景、涉及的人物关系、任务所处阶段、触发原因、紧迫程度、要解决的问题、可讨论的选择或用户与语音助手的互动方式。例如，同一类套餐咨询可以分别来自首次选择、家庭共用、账单变化、出行前准备、准备变更或解释条款；具体取哪些维度必须由当前 Scenario 自然支持，不能虚构不相容的外部事实或风险。

不要让每条goal都遵循同一种pattern 比如 “了解”“我想”“先……再……”或“和语音助手……”的表达。表达入口变化应伴随任务语义和情境的实际变化；去找到现实中尽可能多样化的实际场景以及能够被覆盖的自然方向。

[生成要求]
- goal 要比 Scenario 名称具体，直接表达本次 episode 的用户结果或者需求，并且能够由 audio-only 对话支持。不要把 actor 的讲解、整理、提醒、生成或回读动作本身当成目标，也不要把外部系统已被查询、写入、发送或修改当成结果。
- goal 要与冻结的 `task_style` 相容，但不要求固定动词、固定句式或固定的多阶段结构；开放式互动可以自然展开主题，结构化整理要有材料处理结果，混合型要让通用理解与具体材料判断都发挥作用，常识问答保持单一 topic 和简单的多轮追问空间。
- role_relation 使用明确的虚拟关系和具体主体，不使用泛化称呼。
- task_familiarity 与场景合理相容， 不要默认就是 medium，比如很多设备检查，或者学习交流的场景，用户可能是没有什么熟练度的。或者有些专业场景，用户的熟练度也可能很高。
- voice_profile 采用一段连贯、简洁的自然语言声音描述，必须包含性别呈现和感知年龄段。感知年龄可以是青少年、二十多岁、三十多岁、四十至五十多岁或老年人；请根据用户角色、生活阶段和当前情境选择合理年龄，不要默认所有用户都是三十多岁。只要与场景相容，不同年龄段都可以出现；年龄差异应自然体现在音色、能量、语速或气息上，不要为了制造差异而强行改变角色。场景存在明显压力、身体不适或时间压力时，明确写出对应的情绪、能量或语速信号，例如疲惫、紧张、气息偏弱或语速明显加快。口音、音高、音色、吐字等其它维度按需选择，不要求全部出现。只描述听起来是什么样，不写任务名称、任务对象、行动目的或“因为……所以……”的解释，不写成字段清单、JSON、renderer 选项或控制标签。
- 个人姓名、联系方式、账号、证件、订单号、车牌和精确私人地址必须使用生成的仿真值；城市、街道、地铁线、医院、公园等公共地点可以使用真实名称，但不得把真实地点与可识别的真实个人信息绑定。所有自由文本仍需具体，不使用模板符号、空值或泛指实体。
