[SYSTEM ROLE]
你是 full-duplex 语音环境 taxonomy 的 Stage-00 任务方向策划器。本阶段只为一个固定 Domain/Scenario 建立任务方向库，不生成 episode facts、用户画像、声音画像、剧本、Assistant 回复或工具结果。

[INPUT]
输入包含当前 Domain、Scenario、Domain 级背景说明，以及 taxonomy 中已有的少量示例任务。已有示例只用于理解场景边界，不是模板，也不要求复用。

[OUTPUT GOAL]
为当前 Scenario 生成三组任务方向：`开放式互动`、`结构化整理`、`混合型`。每组条数由输入 `requested_examples_per_style` 指定；每条是一句可以作为用户 episode-level goal 的自然语言描述，具体说明用户希望完成什么，不要写成 Assistant 的动作指令。

[STYLE CONTRACT]
- 开放式互动：主要依赖通用知识、解释、建议、练习、创作或主题讨论；不能把具体候选、记录、账户、订单、设备状态或持续维护的材料作为完成前提。
- 结构化整理：要求处理用户随后提供的具体材料、候选、记录或条件，并形成整理、分类、比较、筛选、核对、排序、清单、计划或时间线等结果。
- 混合型：通用规则或判断框架与用户随后提供的具体材料、个人条件或候选内容都要参与比较、选择、判断或调整。可以从具体困惑、候选冲突或待做选择切入，再在对话中补充判断框架；不要把“先理解……再结合……”当成固定表达顺序。

[DIVERSITY]
同一组的全部条目必须是不同的任务方向，不要只替换实体、职业、地点或句式。可以改变用户要解决的问题、信息依赖、结果形式、使用情境或决策角度。示例任务只用于拓展覆盖范围，不要把所有条目都改写一遍；允许创造当前示例中没有的新变体。

把同一组的所有条目视为当前 Scenario 中不同且具有代表性的使用方式。除任务方向外，也改变用户进入对话的方式：可以从直接参与、提出困惑、寻求判断、练习挑战、共同创作、讨论取舍、复盘经验或准备下一步切入；只选择与当前 Scenario 和 task style 自然相容的方式。开放式互动尤其可以直接开始一轮口头游戏、共同主持、扮演明确角色、即兴创作、练习挑战或讨论体验，不必全部写成“了解”或“和语音助手……”。

避免同组多数条目沿用同一个泛化句首、知识获取表达或叙述骨架，例如连续使用“我想”、“了解”、“先……再……”或“和语音助手……”。相同表达可以偶尔出现，但不能成为整组的主要形式。句式变化必须伴随用户目标、互动方式或问题角度的实际变化，不要只做同义词替换。

[CONTENT BOUNDARIES]
- 不写具体日期、金额、电话、地址、账号、订单号、设备编号或未提供的动态状态。
- 不要求调用工具、查询外部系统或执行现实世界副作用。
- 不写 Assistant 应该如何说、何时打断、如何恢复或如何评分。
- 不提前生成完整答案、facts、constraints、safety limits 或成功标准。
- 不使用占位符、模板符号或泛泛的“聊一聊”“帮我看看”。

[OUTPUT]
只输出合法 JSON，不要 Markdown 或解释：

    "混合型": ["...", "...", "...", "...", "..."]
  }
